# Day 06｜先有測試案例，再談 AI 準不準：建立虛構履歷與職缺資料集

> Recap: 昨天畫面做出來了，但我測試的方式還是「貼一份履歷、看一眼、覺得還不錯」

每次貼的履歷都不一樣，結果變好，我分不出是 prompt 的功勞還是題目變簡單
接下來幾天每天都在改 prompt，改之前得先有一批固定的題目

## 全部虛構

履歷是高敏感個資，而這個系列要公開，資料集得跟著公開，所以十份履歷全是捏的
email 一律 `@example.invalid`，電話用 `0900-000-00X` 保留號段

Day 08 要測 PDF，我很可能隨手丟一份真的進去再 `git add .`
所以 `data/resumes/.gitignore` 先全擋、再白名單：

```gitignore
*
!.gitignore
!.gitkeep
!sample-*.txt
!sample-*.pdf
```

黑名單漏一條是外洩，白名單漏一條只是檔案沒進版控

## 每份履歷都有它要測的毛病

原本寫的是「生 8 到 12 份不同職能」
但十份漂亮的履歷，只能測出模型在理想輸入下會不會動

所以反過來，先列我想測什麼，再為每項生一份：

| 標記 | 想測出什麼 |
| --- | --- |
| `vague` | 通篇「負責開發」，會不會腦補細節 |
| `quantified` | 原文有 QPS、P99，會不會誇大 |
| `skill_gap` | 職稱與技能不相稱，看不看得出來 |
| `timeline_gap` | 沒說明的空白期，抓不抓得到 |
| `explained_gap` | 已說明原因的空白期，會不會**誤判** |

最後兩個是一組
只做前者，模型會越調越多疑，最後對每個轉職者都喊一句「有未說明的空白期」

## 沒有答案卷，就只是素材

十份履歷、六份職缺都只是輸入
`data/index.json` 裡另外有 24 組我自己標的期望結果，有這個才叫測試集

適配只分 strong / partial / weak 三級
原本想標 0 到 100 分，試三組就放棄 —— 同一份今天 72、明天 65，自己都重現不了的刻度等於假裝精確
三級各綁一個決定：去面試、要補強、不要投

裡面埋了陷阱
八年 Tech Lead 對初階後端職缺我標 `weak`：六項必備他全部超出，關鍵字比對會給滿分，但這個媒合實務上不會發生
自學一年的轉職者對同一個職缺標 `strong`，因為職缺明文寫「或具備可展示的完整專案作品」

24 組全是自己讀完標的
拿模型標的答案去評模型，只會評出「它跟自己有多像」

## 測不到的事

模型生的履歷太乾淨，日期統一、沒有錯字，真實履歷是 PDF 轉出來的爛排版
這批能測判斷，測不了解析的韌性，那是 Day 08 的事

版本：資料集 v1.0（10 份履歷 / 6 份職缺 / 24 組期望結果）
