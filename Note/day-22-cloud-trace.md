## 素材：從 Day 04 移過來

### Day 04 留下的一個待驗證決定

`analyzer.py` 目前每次請求都重建 genai Client

當時的理由是 client 本身很輕，而「憑證過期但物件還活著」這種問題很難查
但那是憑感覺，沒有數字

今天有 Trace 了，可以看出建 client 在一次請求裡佔多少時間，再回來決定要不要改成單例

### 順便：一個只有在服務裡才會出現的 bug

Day 04 把腳本搬進函式時，我原本寫成這樣

```python
resp = _client().models.generate_content(...)   # 會炸
```

結果拿到

```
RuntimeError: Cannot send a request, as the client has been closed.
```

原因是 `_client()` 產生的 Client 物件沒有任何人持有
`.models` 取出來之後那個暫時物件就可以被回收，而它被回收時會關掉底下的 httpx 連線
就在請求真的送出去之前

腳本裡不會遇到，因為 `client` 是模組層級變數，程式跑完之前都活著
一搬進函式，生命週期就變了

修法只是存成區域變數。但這件事說明了物件生命週期在服務裡值得被看清楚，而這正是 Trace 的工作
